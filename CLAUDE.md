# Accountancy Boards Practice Hub — maintainer notes

## Architecture
- `index.html` is the whole app (one self-contained file). It is GENERATED by `python3 tools/build.py`. Never hand-edit it; edit the sources in `tools/` and rebuild.
- Home view shows ONE BOX PER TOPIC (user request). Topics are registered in the `TOPICS` list in `tools/build.py`; list order = home order.
- Home is grouped by subject. Management Services: Cost Concepts & Cost Behavior (`cost_*`), CVP Analysis (`cvp_*`; Sales Mix is an extra CVP tab). Taxation: one box opening the Tax handouts.
- Taxation (`tools/tax_section.py`) is built from Naia's study workbook `tools/tax_source.xlsx` (parsed by `tools/tax_parse.py`). Each sheet becomes a chapter page; `GROUPS` sets the contents order, names and priority labels. To update tax notes, edit the xlsx and rebuild. Keep sheet colors/prefixes (BIG IDEA, HOOK:, TRAP:, ADDED BY ME, 5 THINGS) — the parser relies on them.
- Navigation uses the URL hash (`#cost`, `#cvp`, `#tax`, `#tax-<slug>`, `#tax-<slug>--<section>`) so the phone back button works. Text like "see the Dividends tab" or "RATES tab, Section C" is auto-linked; following such a link shows a "↩ Back to …" pill that returns to the exact scroll spot.
- Tax calculators are hand-written JS in `CALC_JS`; each shows its base formula (`FX` list) and a "Deductions" note saying when deductions apply and why not (`DN` list), both in the same order as `CALCS`, above the inputs. Lists the reader must compare (brackets, scales) go in `{th:[...],rows:[...]}` mini tables, never in one run-on line; every result row carries its substituted computation (4th item of the row), shown by tapping the number or the "=" button, or by hovering the number on desktop. The callout stays inside the calculator card, and must match the workbook's CALCULATORS examples (212,500; 150,500; 500,000; 53,846.15; 30,000; 870,000; 120,000; 200,000; 60%).
- Each topic has tabs: Handout, Questions, plus optional extra tabs. Element ids are prefixed with the topic id (e.g. `cost-s3`) so they never collide.
- To add a topic: write `tools/<topic>_questions.py` (exports `Q`), `tools/<topic>_handout.html`, then add a dict to `TOPICS`.
- JS is minimal: view switching, tab state in localStorage (wrapped in try/catch), and Reveal/Hide answer toggles.

## Style rules (set by the user)
- Font: Arial only. Theme: light pink and white.
- Keep it simple: problem, question, choices, Reveal answer button. No timer, scoring or animations unless asked.
- Peso sign is ₱. Numbers use thousands separators.

## Questions (`tools/*_questions.py`)
- Source pattern: take the review handout's practice questions, keep the problem TYPE, change givens and wording. CVP = 3 sets of 13 + 1 bonus; Cost Concepts = 4 sets of 10.
- Each problem type is a function (e.g. q1…q13 in CVP, t1…t10 in cost) that takes the givens and COMPUTES the correct answer, distractors and solution steps. Never type an answer by hand.
- `part()` asserts the 4 options are distinct. Options are shuffled with a fixed seed so letters stay stable between builds.
- Givens are chosen so answers come out as whole numbers (DOL may have decimals).
- Solutions follow the handout's formulas (CM per unit/ratio, (FC + profit) ÷ CM, after-tax ÷ (1 − t), package method for sales mix, DOL = CM ÷ profit).
- Distractors model real mistakes: forgetting the tax gross-up, using the variable cost ratio, using a single product's ratio, etc.

## Handouts (`tools/*_handout.html`)
- Written in our own words. Do NOT paste text or branding from review center handouts (they forbid distribution and this repo is public).

## Verification
After any change: run `python3 tools/build.py`, check the console count, and syntax-check the inline script (`node --check` on the extracted `<script>`). Check the page at 400px width for horizontal overflow, using real phone emulation (e.g. Playwright `devices["Pixel 5"]`), since GitHub Pages serves index.html as-is.
- index.html must stay a full document (`<!doctype html>`, `<meta name="viewport" content="width=device-width, initial-scale=1">`). Without the viewport tag phones render it at desktop width and the text looks tiny.
- Phone styles live in the `@media (max-width:600px)` block (base text 18px).
